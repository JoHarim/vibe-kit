# vibe-kit 개선 백로그 (2026-07-30 멀티에이전트 리뷰 결과)

> 7개 렌즈(기획·훅·스킬·문서·툴체인·연동·실사용 적합성) 병렬 리뷰 45건 → 비판 검증으로 중복·과잉 16건 기각 → **21건 확정**.
> 담당: `claude`(기획·문서·설계) / `codex`(코드 구현) / `user`(회장님 결정).
> 각 항목의 **지시문**은 해당 담당 AI 세션에 그대로 붙여넣을 수 있는 형태다.

## 총평

킷의 간판 기능(계획 게이트·진행률·환경 점검)이 **Windows에서 아예 안 도는 확정 버그**가 여러 개 있었고(원 킷이 맥 부트캠프용이라), 실제 프로젝트 대부분이 **바닐라 정적 PWA + Netlify**인데 킷에는 netlify가 0회 등장한다. 실행 축은 4개:

1. **Windows 확정버그 소탕** (P1-1~3) — 전부 소수정, 즉효
2. **정적 PWA + Netlify 트랙 신설** (P1-5, P1-6, P1-8)
3. **blueprint 8단계 개편** (P1-4) — 설계문서 1장을 먼저 확정한 뒤에만 파일 수정 (충돌 방지)
4. **2-AI 분업 지원** (P1-7) — Codex는 `.claude/CLAUDE.md`를 안 읽으므로 AGENTS.md가 킷 규칙을 전달할 유일한 통로

**작업 순서 주의 (충돌 방지)**
- P1-1 + P1-2 + P1-3은 **같은 PR로 묶는다** — adopt `--update`(P1-3)가 없으면 훅 수정이 기존 프로젝트(setlog 등)에 전파되지 않는다.
- blueprint 관련 파일(SKILL.md·question-bank·templates)은 **P1-4 설계문서 확정 전에 만지지 않는다.** P2-9(잔재 정리)도 P1-4 이후.
- P2-7(테스트·CI)은 P1-1~3 머지 후. P3-2·P3-4는 P3-1 결정/P2-7 이후.
- P1-8+P2-3(같은 파일), P2-4+P2-6(같은 파일)은 각각 같은 세션에서 처리.

## P1 — 당장 (8건)

### P1-1 · Windows 훅 확정버그 3종 일괄 수정 〔codex · small〕
(a) `settings.json` 훅 6종의 `$CLAUDE_PROJECT_DIR`는 POSIX 문법이라 Windows에서 전 훅이 'Cannot find module'로 즉사(fail-open이라 무증상) → 상대경로 `node .claude/hooks/xxx.mjs`로 교체. (b) `plan-gate.mjs` 30행이 슬래시만 검사해 Windows 백슬래시 경로에서 게이트가 한 번도 발동 안 함 → rel 계산 직후 `rel.split(sep).join("/")` 1줄. (c) `progress-html.mjs` 27행 상위 탐색이 드라이브 루트에서 무한루프 → `prev` 수렴 종료조건.
> **지시문**: settings.json 훅 6종을 상대경로(node .claude/hooks/xxx.mjs)로 바꾸고, plan-gate.mjs rel 계산 직후 구분자 정규화 1줄(rel.split(sep).join("/"))과 progress-html.mjs 상위탐색에 prev 수렴 종료조건을 넣은 뒤, Windows 실기기에서 ①apps/ Write 차단 발동 ②하위 폴더에서 연 세션 두 케이스를 검증하라.

### P1-2 · setup.mjs Windows 전면 수리 + 점검 항목 확충 〔codex · small〕
`/bin/sh` 하드코딩으로 Windows에서 7개 도구 전부 '없음' 출력(실측). spawnSync `{shell:true}` 크로스플랫폼화, 안내 문구 OS 분기(winget/scoop 병기·`&&` 제거·`npm i -g pnpm` 대안), TOOLS에 netlify CLI·Playwright 브라우저 확인 추가, README에 `npx playwright install chromium` 1줄.
> **지시문**: setup.mjs의 도구 탐지를 spawnSync(cmd, [flag], {shell:true})로 바꾸고 안내 문구를 OS 분기하며, TOOLS 점검에 netlify CLI와 Playwright 브라우저 확인을 추가하고 README 시작 블록에 npx playwright install chromium 한 줄을 넣어라 — Windows PowerShell에서 node scripts/setup.mjs 실행 결과로 검증.

### P1-3 · adopt.mjs 자기-adopt 가드 수정 + `--update` 모드 신설 〔codex · small〕
가드 무력화 실측(`--into C:\dev\vibe-kit\docs --dry`가 중단 없이 진행) → `path.relative` 기반 판정으로 교체. `--update` 모드: hooks·skills·settings 훅 항목만 갱신, `plan.md`·`profile.md`·`docs/plan/`·`.env`는 불가침. **P1-1·P1-2와 같은 PR 필수** — 이게 킷 수정을 기존 프로젝트로 전파하는 유일한 경로다.
> **지시문**: adopt.mjs 51행 자기-adopt 가드를 path.relative 기반 판정으로 교체하고, hooks·skills·settings 훅 항목만 갱신하며 plan.md/profile.md/docs/plan/.env는 불가침인 --update 모드를 추가한 뒤 README에 기존 프로젝트 반영법 3줄을 넣어라 — Windows에서 자기-adopt 차단과 --update 불가침 목록을 각각 실행 검증.

### P1-4 · blueprint 8단계 통합 개편 — 설계문서 선행 〔claude · large〕
카드 '추가' 제안 4건(저장·배포 트랙 분기, 출시·수익화 단계, PWA 조건부 카드, GA 슬롯)과 '감축' 제안 2건(라이트 트랙·스피드런)이 상충 → 설계문서 1장 먼저: ⓐ3단계 직후 **트랙 분기 1회 판정**(브라우저저장+정적배포 vs 서버+DB) ⓑ트랙 안에 출시·PWA 질문 배치(PWA 후속 3문: 오프라인 범위·설치 유도·업데이트 정책 — setlog 캐시 고착 사고가 근거) ⓒ**라이트=스피드런 통합**(profile.md 고정 기본값 있으면 확인 카드로 압축, 풀 60~90분/라이트 20~30분 명시). templates에 launch-checklist.md(OG태그·측정·첫 공개 채널·수익 사다리) 신설, profile.md 고정 기본값(정적 PWA+Netlify·구현=Codex — 공개 레포이므로 스택·작업방식 수준까지만).
> **지시문**: '트랙 분기 1회 판정(정적 라이트/풀스택) → 트랙별 출시·PWA 질문 배치 → 라이트=스피드런 통합'의 blueprint 개편 설계문서 1장을 확정하고, 그 문서 기준으로만 SKILL.md·question-bank·templates(launch-checklist 신설 포함)·profile.md를 수정하라 — 설계 확정 전 blueprint 파일을 만지는 다른 발주 금지.

### P1-5 · deploy 스킬 Netlify 분기 + CLAUDE.md CLI 금지 예외 〔claude · medium〕
현 deploy 스킬은 Vercel 웹콘솔 전제인데 실배포 다수는 Netlify CLI. 감지 분기: netlify.toml→`netlify deploy --prod` / next.config→Vercel 웹콘솔 / 정적(서버 .env 없음)→'JS에 박힌 키는 전부 공개' 경고. CLAUDE.md 'CLI 설치 권하지 마라'에 Netlify CLI 예외 1줄. security-reviewer 정적 스택 문구 보강(부속).

### P1-6 · 정적 PWA+Netlify 스캐폴드 + e2e 하드코딩 수정 〔codex · medium〕
`templates/static-pwa`(index.html·manifest·SW 즉시갱신 전략·netlify.toml)를 워크스페이스 **밖** 단일 폴더로 신설('정적 프로젝트는 npm만으로 시작'). 실측 결함: e2e webServer `pnpm --filter @vibe-kit/web dev` 하드코딩, smoke.spec 8행 'vibe-kit' 텍스트 기대(adopt된 프로젝트에서 통과 불가). INGREDIENTS.md Netlify 행·`.env.example` NETLIFY_AUTH_TOKEN·README adopt 격상.
> **지시문**: 워크스페이스 밖에 templates/static-pwa(index.html·manifest·SW 즉시갱신·netlify.toml)를 만들고, e2e webServer 하드코딩과 smoke.spec의 'vibe-kit' 텍스트 기대를 프로젝트-비종속으로 고치며, INGREDIENTS.md Netlify 행·.env.example NETLIFY_AUTH_TOKEN·README adopt 격상까지 한 커밋으로 — 스캐폴드는 npx serve로 띄워 SW 등록까지 실행 검증.

### P1-7 · AGENTS.md 신설 + handoff 스킬 — 2-AI 분업 지원 〔claude · medium〕
**리뷰 전체에서 실사용 가치 최대 단일 항목.** Codex CLI는 `.claude/CLAUDE.md`·skills를 안 읽고 AGENTS.md를 읽는다 — 킷 핵심 규칙(Karpathy 4원칙·`===`만 사용·NEXT_PUBLIC_ 금지·보안 치명 3종)이 구현 AI에 전달 안 되는 상태. (1) AGENTS.md — 코딩 규칙만 **참조형** 미러링(이중 관리 드리프트 방지) (2) handoff 스킬 — 트리거 "코덱스한테 넘기자", plan.md 블럭 1개→자기완결 작업지시서(`docs/plan/handoffs/`), 복귀 시 code-reviewer diff 리뷰까지 한 사이클 (3) README 분업 흐름 1절.
> **지시문**: 코딩 규칙만 참조형으로 미러링한 AGENTS.md와, plan.md 블럭 1개를 자기완결 작업지시서로 뽑고 복귀 시 diff 리뷰까지 안내하는 handoff 스킬을 신설하고, README에 분업 흐름 1절을 추가하라 — blueprint 산출물 단계의 AGENTS.md 갱신 1줄은 P1-4 설계문서와 맞춰라.

### P1-8 · 실행·검증 스킬 4종에 정적 사이트 폴백 〔claude · small〕
