# handoff: 코덱스한테 넘기기

기획·리뷰는 여기(Claude)서 하고 구현은 다른 AI(Codex CLI)가 하는 분업에서, 두 AI 사이에 오가는 건 **작업지시서 한 장**뿐이다. 주방장이 요리사에게 넘기는 주문서와 같다 — 요리사는 홀에서 오간 대화를 못 들었으니, 주문서 한 장만 보고도 그 요리가 나와야 한다.

## 철칙 (Iron Law)

**지시서 한 장 = 블럭 한 개 = 자기완결.** Codex 는 이 대화도 `.claude/CLAUDE.md` 도 읽지 않는다(읽는 건 루트 `AGENTS.md` 뿐). 그러니 지시서엔 배경·파일 경로·화면 명세 요약·제약·완료 기준·검증 방법이 전부 들어 있어야 한다. "저번에 말한 그거"는 지시서에선 죽은 말이다.

## 절차

1. **넘길 블럭 하나 확정.** "plan.md 에서 어느 블럭을 넘길지 먼저 정할게요." 라고 말하고, plan.md 의 체크 안 된 블럭들을 AskUserQuestion 카드로 묻는다. 순서상 다음 블럭을 "(추천)" 1순위로. plan.md 에 블럭이 아직 없으면 "기획이 먼저예요 — '기획하자' 라고 해보세요" 라고 안내하고 멈춘다.
2. **재료 모으기.** 그 블럭의 스텝·완료 기준(plan.md), 걸린 화면 명세(`docs/plan/screens/*.md` — 예외 5종 포함), 걸린 표(05-db.md), 걸린 결정(06-decisions.md)을 읽어 요약한다. 요약이 원본과 어긋나면 안 된다 — 지어내지 말고 원본에서 옮겨라.
3. **지시서 쓰기.** `docs/plan/handoffs/YYYY-MM-DD-블럭명.md` 로 저장한다. 형식:

    ```markdown
    # 작업지시서 — 블럭 N. [기능명] (YYYY-MM-DD)

    ## 배경 (2줄)
    [이 프로젝트가 뭔지 한 줄 / 이 블럭이 왜 지금인지 한 줄]

    ## 만들 것
    완료 기준: [plan.md 블럭 완료 기준 한 줄]
    - [ ] N-1. [스텝] — 확인: [눈으로 보는 방법]
    - [ ] N-2. ...

    ## 수정·생성할 파일
    - [경로] — [무슨 역할, 새로 만드나 고치나]

    ## 화면 명세 요약 (원본: docs/plan/screens/S?-이름.md)
    - 구성·행동: [버튼·입력마다 한 줄]
    - 예외 5종: 비었을 때 [ ] / 로딩 [ ] / 실패 [ ] / 권한 없음 [ ] / 잘못 입력 [ ]

    ## 지킬 제약 (전체 규칙은 루트 AGENTS.md — 이 블럭에 특히 걸리는 것만)
    - [예: 이 표는 soft delete, 비교는 === 만, 키는 .env 에서만]

    ## 완료 기준 체크박스 (전부 체크돼야 끝)
    - [ ] [기능이 실제로 도는 증거 항목들]
    - [ ] 예외 5종 처리됨
    - [ ] 커밋하지 않고 멈춤 (리뷰는 Claude 쪽에서)

    ## 검증 방법
    - [실행 명령 / 열 화면 / 눌러볼 순서 / 기대 결과]
    ```

4. **넘기는 법 안내.** "이 파일 내용을 Codex CLI 에 붙여넣거나, Codex 에게 `docs/plan/handoffs/... 읽고 그대로 해줘` 라고 하면 됩니다." 라고 안내한다. 루트에 `AGENTS.md` 가 없으면 먼저 만들라고 짚는다 — 그게 없으면 킷의 코딩 규칙이 구현 AI 에게 전달되지 않는다. 이미 있으면 `.claude/CLAUDE.md` 와 어긋난 데가 없는지 한 번 훑고, 다르면 원본(CLAUDE.md) 쪽으로 AGENTS.md 를 맞춘다.
5. **복귀 사이클 안내.** "Codex 가 끝내고 돌아오면 '리뷰해줘' 라고 하세요 — code-reviewer 서브에이전트로 git diff 를 검사합니다." 라고 미리 알린다. 리뷰 통과면 plan.md 체크박스 갱신과 커밋을 제안하고, 수정거리가 나오면 같은 지시서 하단에 `## 수정 라운드 (날짜)` 절로 덧붙여 그 파일을 다시 Codex 에 넘기게 한다.

## 금지

- 블럭 두 개 이상을 한 지시서에 담기 (한 장 = 한 블럭).
- "screens/S1.md 참고" 처럼 참조만 적고 요약을 생략하기 (자기완결 위반 — 경로와 요약 둘 다 넣는다).
- 지시서에 plan.md·기획 문서에 없는 기능을 즉석에서 발명해 넣기 (기획 변경이면 blueprint 부분 발동·변경 제안서가 먼저).
- Codex 가 만든 코드를 리뷰 없이 plan.md 에 체크 처리 (plan.md 체크는 리뷰 통과 후 — AGENTS.md 체크박스 규칙과 한 몸이다).
- .env 읽기·쓰기, 지시서에 키 값 적기 (키 이름만).
- 지시서에 이모지.

## 막히면

블럭이 한 장에 안 담길 만큼 크면 지시서를 스텝 1~2개짜리로 쪼갠다(파일명 뒤에 `-a`, `-b`). 그래도 크면 블럭 자체가 큰 것이니 blueprint 로 블럭 분해가 먼저다.

## 졸업

이 스킬 없이도 기억할 세 마디: **블럭 하나 고르고 → 한 장에 다 담고 → 돌아오면 diff 리뷰.**
